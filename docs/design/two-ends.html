Two ends and a line

The panel at the top of the map, working, with the store replaced by 42 fixed names and a timeout. One box that grows into an edge — downward, so it never has to fight the controls for width. A pick in either end writes, so the same widget fans out from one node or fans in to one.

Why it is shaped this way, and what was turned down for it, is ADR 0013. What the real one is wired to is join.ts; this page is the behaviour alone, which is the part that needs driving rather than reading.

The line is constant. It says what the window is for and nothing else — write state lives in the receipts, and a line that varied would say the same thing twice.

      2 · The room, at four widths

      Drawn to scale from the app's own numbers: the HUD is 232px plus its padding at 16px in, and the controls sit 16px from the right. Three widgets against the same controls — the stacked one, and side-by-side ends drawn twice, once staying centred as they grow and once anchored by their left edge.

      A side-by-side end is 240px, the narrowest that still fits a create row. Left-anchored, every pixel of its growth runs toward the controls; re-centred, half of it runs the other way. What each costs is 0013.

      This is the wide room, and it is the only one there is to share: past the breakpoint at the foot of app.css the strip is the panel's alone and the HUD and the controls go to the foot of the window. The comparison still decides the shape, because a wide window is where the widget has neighbours to run into at all.

      3 · What to look for

      TryWhat it is showing
      kav ↵ The far end and the line arrive on the pick, not on the keystroke: the list opens into exactly the space the far end occupies, so appearing while you type would mean appearing under the list.
      Tab, cor ↵ Fan out, and the camera stays on the anchor. Arming flies, firing does not — so the end you are running names through never drags the view, whichever end that is. Fill the second end first instead and you fan in, with the camera on the far anchor by the same rule.
      Now type in the first end and pick Fan in: the far end holds, the first varies, and each pick writes. This is what a symmetric widget buys, and also why a pick there is no longer a safe read. The undo is the whole answer to that.
      Watch which end empties The end that fired, so the next name goes straight in. Fanning out empties the second; fanning in empties the first.
      Read a receipt It names the pair, not a target. With both ends fire-able there is no target — and a receipt outlives the pair that made it, so a single name would read against whatever the widget shows by then.
      Build a-b-c-d with ⌘↵ A path is the shape this widget would otherwise be worst at: every node named twice, once as a target and again as the next source. Hold ⌘ on the pick and the name just written takes the other end, so the caret never moves and each node is named once. The camera goes with it, since that end is now the armed one. What it spends is the anchor you were fanning from — two ends hold one anchor, and the moving one takes its seat.
      Now click a name in a receipt The same chain, reaching what ⌘↵ cannot: any write that landed, however far back, rather than only the one just fired. It goes into the first end and the caret lands in the second. Loading is not writing, which is what lets both names be live.
      Clear one end The widget stays open. Shrinking while the other end still holds a name would leave an armed endpoint with nowhere to aim, and no way back except retyping it.
      Clear both Now it shrinks. Receipts stay where they are, below the part that collapsed.
      Esc, then Esc The first puts the list away, the second puts the widget away — both ends and the focus with them, in one key from either end. One end at a time is what leaves an anchor armed in the end you are not looking at, which is the state this is the way out of. On the real page / is the way back in.
      zibb ↵ Nothing carries the name, so the create row takes the highlight, the box goes dashed, and there is nowhere to fly. Nothing is written until the other end fires.
      Fire the same pair twice The store refuses the second — they are already joined — and the refusal is the only place that answer can come from, since the page knows only the edges it has loaded.
